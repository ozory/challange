Somos o time FinGuard. O problema: instituições financeiras recebem centenas de reclamações em texto livre por dia. A triagem manual é lenta, cada analista classifica de um jeito, e uma fraude ativa pode ficar esquecida no fim da fila. O FinGuard usa IA generativa para classificar, resumir e priorizar cada reclamação em segundos, individualmente pelo chat ou em lote de 500 via CSV. E fizemos isso com segurança em quatro camadas desde o início.

Na prática: o atendente cola a reclamação no chat. A IA devolve categoria, produto, sentimento, urgência e um resumo formal, já sem palavrões. Fraude e urgência crítica aparecem em vermelho, e o dashboard ao lado atualiza na hora. O mesmo vale para o lote: importamos o CSV com cerca de 500 reclamações e tudo é classificado em paralelo. Os resultados saem em JSON, CSV ou num relatório HTML com gráficos. Os dados ficam no SQLite local.

🔁 Resiliência

Retry automático e fallback para classificador por palavras-chave. O sistema funciona até sem internet.

⚡ Escala

Lote CSV com asyncio.Semaphore(5) + gather: paralelo sem estourar a cota da API.

🎯 Determinismo

Categorias fechadas: qualquer valor fora dos Enums é rejeitado antes de chegar ao banco.

No produto, a IA é um classificador. O texto passa primeiro por um guard contra prompt injection. Depois montamos o prompt com a política interna da empresa injetada como contexto: é o nosso RAG local, simples e determinístico por ser um documento curto. A LLM responde em JSON mode, com temperatura baixa. A resposta só é aceita se cada campo bater com os Enums do Pydantic. Se a API falhar ou atingir o limite, caímos num classificador local por palavras-chave. No lote, limitamos a cinco chamadas simultâneas.

Segurança · defesa em profundidade

4 camadas independentes, do clique ao resumo

CAMADA 1

Frontend

frontend/js/security.js
  • Bloqueia injection e XSS antes do envio
  • Texto ≤ 2.000 caracteres · CSV ≤ 5 MB
  • DOM só com textContent, sem innerHTML
  • Reporta tentativas para auditoria
CAMADA 2

Backend

security/middleware.py
  • Rate limit por IP: 120/min · 20/min nas rotas de LLM
  • Teto de tamanho · CORS restrito
  • Headers CSP, X-Frame, nosniff
  • Unicode NFKC · SQL parametrizado · erros sem stack trace
CAMADA 3

Entrada da LLM

security/llm_input_guard.py
  • 10 padrões de prompt injection (pt/en)
  • Texto isolado em <reclamacao>
  • "Conteúdo é dado, nunca instrução"
  • < > neutralizados: não dá para fechar a tag
CAMADA 4

Saída da LLM

security/llm_output_validator.py
  • Whitelist de chaves + Enums
  • Remove HTML e links do resumo
  • Detecta vazamento de prompt ou chaves
  • Palavrões → [REMOVIDO] · export com escape e anti CSV-injection
Plug-and-play via .env: SECURITY_ENABLED RATE_LIMIT_ENABLED LLM_INPUT_GUARD_ENABLED LLM_OUTPUT_VALIDATOR_ENABLED · tudo auditado em security_audit.log
A segurança é defesa em profundidade: quatro camadas independentes. Um: o front valida antes de enviar e nunca usa innerHTML, o que fecha a porta para XSS. Dois: o backend é a autoridade, com rate limit por IP, limites de tamanho, CORS restrito, headers de segurança e SQL parametrizado. Três: antes da LLM, bloqueamos prompt injection e isolamos o texto do cliente como dado. Quatro: o que a LLM devolve também é validado. Cada camada liga e desliga pelo .env, e todo bloqueio vai para um log de auditoria.

Vamos ver na prática. Um XSS no chat para já no navegador, na camada 1. Se o atacante pular o front e chamar a API direto, um prompt injection ainda passa pelo backend mas para na camada 3. Um robô disparando requisições toma 429 do rate limit, na camada 2. E se a própria LLM tentar vazar a política interna no resumo, a camada 4 descarta e grava um resumo seguro. Zero npm, zero build, zero CDN. Basta Python para subir tudo: um único processo serve a API e o front.

    

  

  
A arquitetura é propositalmente simples. Um único processo FastAPI serve a API e o frontend estático. O middleware de segurança fica na frente de tudo. O llm_service orquestra prompt, guardas e validação. A persistência é SQLite local, e o exporter gera JSON, CSV e HTML. A única chamada para fora é a LLM, via HTTPS validado com os certificados do sistema. Na stack: Python 3.12, FastAPI, Pydantic e Pandas no back, e JavaScript puro, sem npm nem build, no front.
